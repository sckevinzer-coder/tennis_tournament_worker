# 테니스 대회 관리 시스템 - 결정사항 문서

## 1. 프로젝트 개요
- **프로젝트명**: 테니스 대회 관리 시스템
- **목적**: 조별리그 후 토너먼트 방식의 테니스 대회를 효율적으로 운영하기 위한 플랫폼
- **기본 사용자**:
  - 운영자 (Organizer): 대회 생성, 참가자 관리, 스코어 입력 등
  - 참가자 (Participant): 본인 경기 스코어 입력, 순위 조회 등

## 2. 기술 스택 결정사항

### 백엔드
- **언어**: Node.js (JavaScript)
- **프레임워크**: Express.js
- **ORM**: Sequelize
- **데이터베이스**: PostgreSQL (운영), SQLite (로컬 개발)
- **실시간 통신**: Socket.io (WebSocket) 또는 폴링

### 프론트엔드
- **프레임워크**: React
- **스타일링**: Tailwind CSS
- **라우팅**: React Router DOM
- **HTTP 클라이언트**: Axios

## 3. 데이터베이스 설계 결정사항

### 테이블 구조
1. **User (사용자)**
   - id, name, email/phone, role, created_at

2. **Organizer (주최자)**
   - id, user_id, org_name

3. **Tournament (대회)**
   - id, organizer_id, name, status, visibility, matchType, doublesMode, created_at

4. **Participant (참가자)**
   - id, tournament_id, user_id, name, affiliation, seed_rank, registered_at

5. **Team (팀 - 복식 팀 페어 모드 전용)**
   - id, tournament_id, name, player1Id, player2Id

6. **Match (경기)**
   - id, tournament_id, type, stage, participant_a_id, participant_b_id, participant_c_id, participant_d_id, team_a_id, team_b_id, sets, winner_id, status, court_number, input_by, updated_at

7. **MatchResult (경기 결과 기록)**
   - id, match_id, user_id, opponent_user_id, result, tournament_id, played_at

8. **Group (조)**
   - id, tournament_id, name, group_size

9. **GroupAssignment (조 편성)**
   - 조별 편성 방식: 랜덤 편성, 시드 편성, 혼합 방식
   - teamId nullable (복식 팀 페어 모드에서 팀 단위 배정 시 사용)

10. **ScoringRule (대회별 테니스 스코어 규칙)**
    - set_format, games_per_set, tiebreak_trigger, tiebreak_points, final_set_tiebreak

11. **RegistrationRequest (참가 신청)**
    - id, tournament_id, user_id, status, requested_at

12. **RankingSnapshot (랭킹)**
    - id, user_id, period, points, rank, calculated_at

### 확장성 고려사항
- User/Organizer/Participant 분리 구조로 인해 향후 회원가입/다중 주최자 기능 확장 가능
- Tournament는 visibility=공개 설정 시 전체 목록에 노출 가능하도록 설계
- MatchResult는 랭킹 계산용으로 추후 배치 처리 로직 연결 가능
- matchType + doublesMode 조합으로 단식/복식 팀 페어/복식 랜덤 3가지 대회 타입 지원

## 4. 권한 구조 결정사항

| 역할 | 권한 |
|---|---|
| 운영자 (Organizer) | 대회 생성(종목 타입/복식 방식 포함), 참가자 추가·삭제, 스코어 규칙 설정, 조 편성, 대진표 생성, 모든 경기 스코어 최종 확정 |
| 참가자 (Participant) | 본인 경기 스코어 입력, 대진표/순위 조회 |

### 입력 충돌 처리
- 양측 참가자가 입력한 스코어가 다를 경우 상태를 "확인필요"로 전환 → 운영자가 최종 확정

## 6. 확장 방향 결정사항

### 1단계 (MVP)
- 대회 1개 운영: 참가자 등록, 조 편성, 스코어 입력, 대진표
- 단식 / 복식(팀 페어, 랜덤 조합) 3가지 대회 타입 지원
- 운영자 1명, 참가자는 대회코드로 간편 입장

### 2단계 (회원 시스템 도입)
- User 회원가입/로그인 정식 도입
- 참가자가 여러 대회 참가 이력 마이페이지에서 조회

### 3단계 (멀티 주최자)
- 여러 Organizer가 각자 대회 등록 가능
- 대회 visibility=공개 설정 시 전체 목록에 노출

### 4단계 (검색/신청 플랫폼화)
- 지역/레벨/일정 기준 대회 검색·필터
- RegistrationRequest를 통한 "신청 → 승인" 흐름

### 5단계 (랭킹 시스템)
- MatchResult 이력이 쌓이면 랭킹 산정 로직 도입
- 유저별 RankingSnapshot 계산 → 마이페이지/전체 랭킹 화면에 노출

### 6단계 (커뮤니티/리워드, 선택)
- 참가 리워드(포인트), 응원/좋아요, 친구 기능 등 테니스타운 스타일 부가 기능

### 8-1. 대회당 동시 진행 코트 수 / 코트 배정 로직

- **결정 (MVP)**: 스키마 변경 없이 `POST /tournaments/:id/generate-matches`에서 court 번호를 매치 순서대로 순환 할당(기본 1코트). `court`에 코트 번호 문자열 기록.
  - UI: `MatchCard` 헤더·`ScoreInput`에 코트 배지(`코트 1`) 표시 + 경기 탭 코트 필터 탭.

### 8-7. 대회 종목 타입별 참가자 등록 화면 분기 (2026-08-30 결정)

- **배경**: 단식/복식 팀 페어/복식 랜덤 3가지 대회 타입이 확정됨에 따라, 참가자 등록 화면이 타입에 따라 달라져야 함.

- **결정**:

| 대회 타입 | matchType | doublesMode | 참가자 등록 UI | 팀 구성 단계 | 조편성 단위 |
|---|---|---|---|---|---|
| 단식 | singles | - | 개인 이름 입력 | 없음 | 개인 |
| 복식 랜덤 조합 | doubles | random | 개인 이름 입력 (단식과 동일) | 시스템 자동 | 조 내 2v2 |
| 복식 팀 페어 | doubles | team | 팀 결성 카드 (선수 2명 검색·선택) | **신청 시 2명이 함께 신청 → 승인 시 Team 자동 생성** | 팀 단위 |

- **핵심 원칙**:
  - 단식과 복식 랜덤은 **개인 등록 UI 공유** — 화면 분기 불필요
  - 복식 팀 페어만 **별도 팀 결성 UI** 필요 (선수 2명 검색 선택 → 팀명 자동 생성)
  - 종목 타입은 **대회 탭에서 설정** → 참가자 탭은 설정값에 따라 자동 분기 (운영자가 참가자 탭에서 직접 바꿀 수 없음)
  - 복식 팀 페어: 조 편성 시 조당 최소 2팀 요건, 4명 미만 조는 ⚠️ 경고 표시

- **구현 영향 파일**: `Dashboard.jsx` (참가자 탭 분기 로직), `api/tournament.js`
- **기능테스트**: 단식/복식 랜덤 → 개인 등록 화면 동일 확인 / 복식 팀 페어 → 팀 결성 카드 노출 확인

### 8-8. 참가자 신청(등록 주체 전환) (12.2, 2026-08-31 결정, 2026-09-01 수정)

- **배경**: 현재 등록은 **운영자 화면**에서 이름을 직접 입력하는 방식. 사용자 요구: ① 등록은 **참가자 역할**에서 대회를 보고 직접 "참가 신청" ② 단식은 1명씩, **복식은 1명이 2명(본인+파트너)을 함께 신청** ③ 파트너는 **참가자 계정(회원)을 검색**해 같이 등록 ④ 운영자 화면 참가자 탭은 **참가자 카드 형태**로 표시.

- **2026-09-01 수정**: 복식 팀 모드에서 개별 등록 후 운영자가 팀을 조합하는 2단계 방식은 번거로우므로, **2명이 함께 신청 → 승인 시 자동으로 Team 생성**하는 1단계 방식으로 변경.



- **결정**:
| 항목 | 설계 |
|---|---|---|
| 신청 주체 | **참가자(ParticipantHome)**: 대회 목록/코드 입장 화면에서 대회 선택 → "참가 신청" (운영자 화면의 직접 등록 폼은 보조로 유지) |
| 단식 | 이름 1명 입력 (본인). `RegistrationRequest { participantName, memberNames:[본인], status:'pending' }` |
| 복식 | **본인 1명 + 파트너 1명 = 2명** 동시 신청 (`memberNames:[본인, 파트너]`). 파트너는 ① **계정 검색**(`GET /auth/users/search?q=` — 회원이름/이메일) ② 자유 이름 입력 폴백 |
| 복식 팀 페어 | 승인 시 2명 `Participant` 생성 + **`Team` 자동 결성** (팀명 자동 "A·B") — 조편성 준비 완료 |
| 복식 랜덤 | 승인 시 2명 `Participant` 생성 (자동 랜덤 팀 구성은 기존 매치 생성 로직 유지) |
| 승인 흐름 | 신청: `pending` → 운영자 대시보드 참가자 탭 **신청 카드**(승인/거절 버튼) → 승인 시 `Participant`(+필요 시 `Team`) 자동 생성 후 카드가 참가자 카드로 전환 / 거절 시 `rejected` (재신청 가능) |
| 운영자 표시 | 승인된 참가자는 **참가자 카드 그리드**(이니셜 아바타+이름+모드/조/팀 배지+수정·삭제) — **랜덤 매치는 기존 참가자 목록 유지** |
| 데이터 모델 | 기존 `RegistrationRequest` 재사용 + **`memberNames`(JSON) 컬럼 추가** (모델+멱등 마이그레이션) |

- **중복 방지**: 같은 대회+이름(또는 이메일) 신청이 `pending`/`approved`로 이미 있으면 409 — 거절된 재신청만 허용.

### 12-4. 복식 랜덤 "게임 수 고정 믹서" — 기존 전체 조합 방식 대체 (2026-09-03 결정·구현)

- **배경**: 기존 복식 랜덤 모드는 조 내 **모든 고유 2v2 조합**(`3*C(n,4)`)을 생성 — 4명→3경기지만 6명→**45경기**, 8명→210경기로 인원이 늘면 사용 불가. 사용자 요구: **인원 수와 무관하게 각자 4게임씩** 치르는 동호회 믹서 방식. 논의 결과 "전체 조합 방식을 남겨둘 필요 없음"으로 확정 — **4명 조 + K=3이 구 방식과 완전히 동일한 결과**(각자 서로 다른 파트너와 1번씩)라 고정 게임 방식이 구 방식을 완전히 포함하기 때문.
- **결정**:
| 항목 | 설계 |
|---|---|
| 총 경기 수 | `ceil(n×K/4)` (n=인원, K=인당 경기 수) — 10명×4게임 → 10경기로 항상 현실적 |
| 인당 보장 | 각자 정확히 K경기. `n×K/4`가 나누어떨어지지 않으면 초과 슬롯을 id 순 +1경기 분배(일부 K+1) |
| 구성 방식 | 라운드별 셔플로 4명씩 묶어 2v2 — **파트너 반복에 높은 페널티**(×100), 상대 반복 페널티로 3가지 분할 중 최소 반복 선택 |
| bye 처리 | 라운드당 `floor(n/4)`경기, 못 뛰는 인원은 **남은 목표 경기 많은 순 → 휴식 적은 순**으로 공평 분배 |
| 게임 수 설정 | 운영자 선택 **2~6 (기본 4)** — `Tournament.gamesPerPlayer` 신설(멱등 마이그레이션), POST/PUT/generate-matches 모두 검증 |
| 대체 범위 | `generateDoublesRoundRobinMatches`(전체 조합) **삭제** → `generateDoublesFixedGamesMatches` 단일화. 기존 대회의 생성 매치는 유지, 재생성 시 새 방식 적용 |
| 수동 경기 추가 폼 | **복식 경기 추가(4명 수동 선택) 폼 삭제 (2026-09-03 추가 결정)** — 수동 추가는 "각자 K경기" 보장을 깨므로 모든 모드에서 일원화: 단식(브래킷)/복식 랜덤(믹서)/복식 팀(팀 리그) 모두 자동 생성만 사용 |
- **프론트**: 대회 생성/✏️설정 폼에 복식+랜덤 선택 시 **"인당 경기 수" select(2~6, 기본 4)** 노출, 경기 탭 안내 문구에 인당 경기 수 표시. **`Dashboard.jsx`의 `dbl` 상태·`handleAddDoubles`·`doubles-form` UI 블록 삭제**
- **구현 영향 파일**: `models/Tournament.js`(+gamesPerPlayer), `bin/startServer.js`(멱등 훅), `utils/matchGenerator.js`(생성기 교체), `routes/tournamentRoutes.js`(검증·옵션 전달·응답 echo), `Dashboard.jsx`(폼 2곳+안내), `README.md`
- **검증**: Jest **95/95 (17 suites)** — 신규: 4명 K=3 구방식 동일성(파트너 쌍 전부 상이) / 6·8명 인당 4경기+파트너 반복 최소화 / 5명 K=2 미분할 +1 분배 / API 기본·override·설정값·400 / 브라우저 E2E **87/87** (신규: 인당 경기 수 select 노출, gamesPerPlayer 기본값 echo, 믹서 매치 생성 4경기·인당 4경기) · 빌드 ✓
