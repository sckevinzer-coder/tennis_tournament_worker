# 테니스 대회 관리 시스템 - 초기 설계

## 1. 개요

- **대회 방식**: 조별리그 후 토너먼트 (녹아웃)
- **종목**: 테니스
- **주요 사용자**: 운영자 / 참가자
- **참가 인원**: 고정 없음, 언제든 추가/삭제/변경 가능
- **실시간 스코어**: 운영자 + 참가자 직접 입력 가능
- **확장 방향**: 지금은 "대회 1개 운영 툴"로 시작하되, 나중에 "테니스타운"처럼 여러 대회를 모아 신청받는 플랫폼으로 확장 가능하도록 구조를 미리 열어둠 (아래 8번 항목 참고)

## 2. 데이터 모델

### User (사용자 - 신규)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| name | 이름 |
| email / phone | 로그인 식별 정보 |
| role | 일반유저 / 주최자 (나중에 다중 역할 가능) |
| created_at | 가입일 |

> User는 "사람" 자체를 나타내는 계정이고, Participant는 "특정 대회에 참가한 기록"으로 분리. 한 User가 여러 대회에 Participant로 등록될 수 있게 구조를 잡아둠 (나중에 유저별 참가 이력 기능으로 자연 확장).

### Organizer (주최자 - 신규)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| user_id | 연결된 User |
| org_name | 주최자/단체명 (개인이면 이름) |

> 지금은 주최자가 나 한 명뿐이어도, Tournament가 특정 Organizer에 속하는 구조로 처음부터 설계 → 나중에 여러 주최자가 각자 대회를 올리는 구조로 확장할 때 테이블 변경 없이 그대로 사용 가능.

### Tournament (대회)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| organizer_id | 주최자 (User/Organizer 참조) |
| name | 대회 이름 |
| status | 모집중 / 진행중 / 종료 |
| visibility | 비공개 / 공개 (신규 - 나중에 "공개 대회 목록/검색" 화면으로 확장 가능) |
| matchType | 대회 종목 타입: `singles`(단식) / `doubles`(복식) — 기본값 `singles` |
| doublesMode | 복식 등록 방식: `team`(팀 페어 신청) / `random`(랜덤 조합) — matchType이 doubles일 때만 유효, 기본값 `random` |
| created_at | 생성일 |

> **matchType + doublesMode 조합으로 3가지 대회 유형 결정:**
> - `singles` → 단식 (개인 등록, 개인 대진)
> - `doubles + team` → 복식 팀 페어 (팀 단위 등록, 테니스타운 정식 복식 방식)
> - `doubles + random` → 복식 랜덤 조합 (개인 등록 후 시스템이 랜덤 팀 구성, 동호회용)

### RegistrationRequest (참가 신청 - 신규, 확장용)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| tournament_id | 대상 대회 |
| user_id | 신청한 유저 |
| status | 신청됨 / 승인됨 / 거절됨 |
| requested_at | 신청일 |

> 지금 단계에서는 운영자가 참가자를 직접 등록해도 되지만, 이 테이블을 미리 만들어두면 나중에 "누구나 신청 → 운영자 승인" 흐름(테니스타운 방식)으로 자연스럽게 확장 가능. 승인되면 아래 Participant로 전환.

### Participant (참가자)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| tournament_id | 소속 대회 |
| user_id | 연결된 User (신규 - 있으면 연결, 없으면 null 허용해 비회원 참가도 지원) |
| name | 이름 |
| affiliation | 소속 (선택) |
| seed_rank | 시드 순위 (선택, null이면 미시드) |
| registered_at | 등록일 |

### Team (팀 - 복식 팀 페어 모드 전용)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| tournament_id | 소속 대회 |
| name | 팀명 (미입력 시 "선수1·선수2" 자동 생성) |
| player1Id | 캡틴 (Participant FK) |
| player2Id | 파트너 (Participant FK) |

> 복식 팀 페어 모드에서만 사용. 단식과 복식 랜덤 모드는 Team 불필요.

### MatchResult (경기 결과 기록 - 신규, 랭킹용)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| match_id | 원본 Match 참조 |
| user_id | 참가자 (User 연결) |
| opponent_user_id | 상대방 |
| result | 승 / 패 |
| tournament_id | 어느 대회에서 발생했는지 |
| played_at | 경기 일시 |

> Match는 "대회 안에서의 경기"를 나타내고, MatchResult는 그걸 유저 단위로 뽑아낸 이력. 나중에 랭킹 계산은 이 테이블을 집계해서 산출하면 되므로, 랭킹 로직이 Match 구조 자체를 건드릴 필요가 없음.

### RankingSnapshot (랭킹 - 신규, 확장용)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| user_id | 대상 유저 |
| period | 랭킹 산정 기간 (예: 2026년 상반기, 또는 누적) |
| points | 랭킹 포인트 |
| rank | 순위 |
| calculated_at | 산정 시점 |

> 랭킹 산정 방식(단순 승수 기준 / ELO 레이팅 / 대회 등급별 가중치 등)은 나중에 결정해도 됨. 지금은 MatchResult가 쌓이는 구조만 만들어두면, 랭킹 로직은 이 데이터를 배치로 계산해서 RankingSnapshot에 기록하는 별도 모듈로 얹을 수 있음 — 기존 대회 운영 로직은 건드릴 필요 없음.

### Group (조)
| 필드 | 설명 |
|---|---|
| id | 고유 ID |
| tournament_id | 소속 대회 |
| name | 조 이름 (A조, B조...) |
| group_size | 조당 인원수 (운영자가 대회 생성 시 설정) |

### GroupAssignment (조 편성 방식)
- **랜덤 편성**: 참가자(또는 팀)를 무작위로 섞어 조당 인원수에 맞게 배분
- **시드 편성**: 시드 순위를 기준으로 강한 선수끼리 겹치지 않도록 조별 분산 배치 (표준 스포츠 시드 배정 방식)
- **혼합 방식**: 시드 지정 인원 우선 배치 후 나머지 랜덤 채움

### ScoringRule (대회별 테니스 스코어 규칙)
| 필드 | 설명 |
|---|---|
| set_format | 세트 수 (1세트 / 3세트 2선승제 등) |
| games_per_set | 세트당 게임 수 (기본 6게임) |
| tiebreak_trigger | 타이브레이크 발동 기준: `5-5` 또는 `6-6` (운영자 선택) |
| tiebreak_points | 타이브레이크 점수제 (7점, 10점 등) |
| final_set_tiebreak | 마지막 세트도 타이브레이크 적용 여부 |

### Match (경기 - 조별리그/본선 공통)
```
Match {
  id
  tournament_id
  type: "singles" | "doubles"
  stage: "group" | "bracket"
  participant_a_id, participant_b_id   // 단식 캡틴 / 복식 캡틴
  participant_c_id, participant_d_id   // 복식 파트너 (nullable)
  team_a_id, team_b_id                 // 복식 팀 페어 모드 전용 (nullable)
  scoring_rule_id
  sets: [
    { set_number, games_a, games_b, tiebreak: {a, b} | null }
  ]
  winner_id
  status: "예정" | "진행중" | "완료" | "확인필요"
  court_number (선택, 다중 코트 운영 시)
  input_by: "운영자" | "참가자"
  updated_at
}
```

### GroupStanding (조별 순위 - 자동 계산)
- 승/무/패, 세트 득실차 등으로 자동 산출
- 단식: 개인 순위 (세트 득실 기준)
- 복식 팀 페어: 팀 순위 (게임 득실 기준)
- 조당 통과 인원수(또는 팀 수)는 운영자가 설정 (예: 조당 2명/팀 진출)

### TournamentBracket (본선 대진표)
- 조별리그 통과자 수 기준 자동 생성
- 2의 거듭제곱이 아닐 경우 부전승(bye) 자동 처리 — 시드 상위자에게 우선 부여
- 라운드별 승자 자동으로 다음 라운드 배정
- 복식 랜덤 조합 모드: 파트너 비고정 특성상 조별 리그까지만 지원 (본선 미지원)

## 3. 권한 구조

| 역할 | 권한 |
|---|---|
| **운영자 (Organizer)** | 대회 생성(종목 타입/복식 방식 포함), 조당 인원수/편성 방식 설정, 참가자 추가·삭제, 스코어 규칙 설정, 조 편성 실행, 대진표 생성, 모든 경기 스코어 최종 확정, (확장 시) 참가 신청 승인/거절 |
| **참가자 (Participant)** | 본인 경기 스코어 입력, 대진표/순위 조회, (확장 시) 여러 대회 신청 이력 조회 |

> 지금은 운영자=나 1명, 참가자=대회코드로 간편 입장이지만, User/Organizer/Participant를 분리해뒀기 때문에 나중에 "여러 주최자 + 회원가입 로그인" 구조로 바꿀 때 데이터 구조 자체는 변경할 필요가 없음.

**입력 충돌 처리**: 양측 참가자가 입력한 스코어가 다르면 해당 경기 상태를 "확인필요"로 전환 → 운영자가 최종 확정

## 4. 화면 구성 (모바일 앱 기준, max-width 430px)

### 공통 레이아웃
- 상단 헤더: 현재 대회명 + 화면 제목
- 하단 고정 탭바 (Bottom Navigation)
- 첫 진입 시 역할 선택 화면 (운영자 / 참가자)

### 운영자 탭 (4개)

**1. 대회 탭**
- 대회 생성/선택/수정/삭제
- 대회 생성 시 종목 선택: 🎾 단식 / 👥 복식
- 복식 선택 시 등록 방식 추가 선택: 👥 팀(페어) 신청 / 🔀 랜덤 조합
- 대회 카드 배지로 종목 타입 표시 (`🎾 단식` / `👥 복식`)

**2. 참가자 탭 — 대회 종목 타입에 따라 분기**

| 대회 타입 | 참가자 등록 화면 | 팀 구성 단계 | 조편성 단위 |
|---|---|---|---|
| 단식 (singles) | 개인 이름 입력 | 없음 | 개인 |
| 복식 랜덤 (doubles+random) | 개인 이름 입력 (단식과 동일) | 시스템 자동 랜덤 팀 구성 | 개인 등록 후 조 내 2v2 조합 |
| 복식 팀 페어 (doubles+team) | **👥 팀 등록 폼 1개 (12.3)** — 선수1 필수 + 선수2 선택 | 폼에서 바로 팀 생성 (2명=완성 팀, 1명=파트너 미정 팀) | 팀 단위 (**완성 팀만**) |

- **단식**: 개인 이름만 입력
- **복식 랜덤 (12.4 변경)**: 개인 신청 → 매치 생성 시 **게임 수 고정 믹서** — 인당 경기 수(2~6, 기본 4)만큼 각자 치르고 매 라운드 파트너/상대를 섞어 2v2 구성. 총 경기 = `ceil(n×K/4)` (기존 전체 조합 `3*C(n,4)` 방식은 경기 수 폭발로 **대체·제거**)
- **복식 팀 페어 (12.3 변경)**: 기존 "참가자 등록 → 팀 결성" 2단계를 **"팀 등록" 1단계로 통합**
  - 폼: 선수1 이름(필수) + 선수2 이름(선택·비우면 **1명 팀**) → 이름 기반으로 참가자 재사용/자동 생성 후 즉시 팀 생성
  - **1명 팀**: 카드에 `➕ 파트너 추가` 버튼 (미소속 참가자 선택 → `PATCH /teams/:id`) — 팀명 자동 갱신 "A·B"
  - **조 편성**: 파트너 미정(1명) 팀은 **자동 제외** + 응답에 `excludedIncompleteTeams` 포함 (완성 팀 0개면 400)

**2-2-1. 진행 방식 (12.5)** — 토너먼트 vs 리그 전용
- `Tournament.format` = `tournament`(기본, 조별리그+본선) | `league`(리그 전용, 순위로 승부)
- **league**: 단식·복식 팀 모두 본선 브래킷(placeholder) 미생성 → 조별 순위(승패·게임득실)로 최종 순위
- 복식 랜덤은 항상 리그 전용(믹서) — 옵션 비활성 표시

**2-2-2. 조편성 원클릭 (12.5~12.6)** — 참가자 탭 조편성 카드
- 🎲 자동 편성: 모드별 권장 조 수 자동 계산 (단식 조당 3명 / 복식 랜덤 모든 조 4명↑ / 복식 팀 조당 3팀, 시드 있으면 실력 분산)
- **조당 인원 칩 프리셋(모드별) = 클릭 즉시 편성** — 칩 하나로 설정+편성 동시 완료 (12.6)
- 실시간 프리뷰 + ▸ 직접 설정(그룹 수·편성 방식, 기본 접힘)

**2-2. 참가자 신청 (12.2)** — 등록 주체를 참가자 역할로 전환
- **신청(참가자 화면 `ParticipantHome`)**: 대회 목록/코드 입장에서 대회 선택 → **"참가 신청"** 버튼 → 신청 폼
  - 단식: 이름 1명 입력 (본인) — `memberNames:[본인]`
  - 복식 랜덤: 이름 1명 입력 (본인) — `memberNames:[본인]` (운영자가 매치 생성 시 랜덤 매칭)
  - 복식 팀: **본인 + 파트너 = 2명** 동시 입력 — 파트너는 **계정 검색**(`/auth/users/search?q=`) 또는 자유 이름 입력 — `memberNames:[본인, 파트너]`
  - 신청 완료 → "승인 대기" 안내 (중복 신청은 409)
- **승인(운영자 대시보드 `Dashboard` 참가자 탭)**:
  - 신청 대기 카드(`pending`) — 멤버명 + **승인/거절** 버튼
  - 승인 시: 단식 `Participant` 1명 / 복식 랜덤 `Participant` 1명 / 복식 팀 `Participant` 2명 + **`Team` 자동 결성** 생성 → 참가자 카드로 전환
  - 거절 시 `rejected` (재신청 가능)
- **참가자 카드 그리드(승인된 명단)**: 이니셜 아바타 + 이름 + 모드/조/팀 배지 + 수정·삭제 — **랜덤 대회는 기존 참가자 목록 유지**
- **데이터**: 기존 `RegistrationRequest` 재사용 + `memberNames`(JSON) 컬럼 추가 (모델 + 멱등 마이그레이션)
- **데이터**: 기존 `RegistrationRequest` 재사용 + `memberNames`(JSON) 컬럼 추가 (모델 + 멱등 마이그레이션)

**2-3. 참가자 화면 개편 (12.7)** — 하단 탭 3개 + 대회 상세

## 7. 향후 플랫폼 확장 로드맵 (테니스타운 참고)

지금 단계(1단계)만 만들고, 나머지는 필요할 때 순서대로 붙이면 됨. 데이터 구조는 지금부터 확장 대비가 되어 있어서 아래 단계로 갈 때 큰 재설계 없이 기능만 추가하면 됨.

**1단계 (지금 - MVP)**
- 대회 1개 운영: 참가자 등록, 조 편성, 스코어 입력, 대진표
- 단식 / 복식(팀 페어, 랜덤 조합) 3가지 대회 타입 지원
- 운영자 1명, 참가자는 대회코드로 간편 입장

**2단계 (회원 시스템 도입)**
- User 회원가입/로그인 정식 도입
- 참가자가 여러 대회 참가 이력을 마이페이지에서 조회

**3단계 (멀티 주최자)**
- 여러 Organizer가 각자 대회 등록 가능
- 대회 `visibility=공개` 설정 시 전체 목록에 노출

**4단계 (검색/신청 플랫폼화)**
- 지역/레벨/일정 기준 대회 검색·필터
- RegistrationRequest를 통한 "신청 → 승인" 흐름
- 알림(접수 시작/마감 임박 등)

**5단계 (랭킹 시스템)**
- MatchResult 이력이 쌓이면 랭킹 산정 로직 도입 (승수 기준 또는 ELO 레이팅)
- 유저별 RankingSnapshot 계산 → 마이페이지/전체 랭킹 화면에 노출
- 이후 대회 시드 편성 시 실제 랭킹 데이터를 자동으로 seed_rank에 반영 가능 (현재는 수동 입력)
- 복식 팀 개인 랭킹 산정 (캡틴/파트너 가중치)

**6단계 (커뮤니티/리워드, 선택)**
- 참가 리워드(포인트), 응원/좋아요, 친구 기능 등 테니스타운 스타일 부가 기능
